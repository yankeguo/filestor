# Agent guide

Reply in the same language as the user.

filestor is a small Go (1.27+) cookie-authenticated browser for one S3-compatible bucket (Aliyun OSS, Qcloud COS, AWS S3, MinIO, …). Treat the code as source of truth. Keep changes focused; do not add frameworks or extra services unless asked. Style reference is **nanollm** (same author's sibling project): single `package main`, std `net/http`, `github.com/yankeguo/rg`, `gopkg.in/yaml.v3`, `github.com/stretchr/testify`, Bootstrap 5.3 dark + icons from jsdelivr with SRI.

## Layout

Single `package main`. No `internal/` split unless the tree clearly outgrows one package.

| File | Role |
|---|---|
| `main.go` | Flags, listen address, graceful shutdown with no deadline (`github.com/yankeguo/rg`) |
| `config.go` | YAML load/validate; S3 endpoint `https://` prefix if missing |
| `auth.go` | HMAC session cookie `filestor`; `requireAuth` 302s to `/login` |
| `server.go` | `net/http` mux, security headers, login/logout, `/` → `/browse`, browse + download/preview handlers |
| `s3.go` | `ObjectStore` (`List`, `ListKeys`, `Get`, `SignGetURL`, `SignPreviewURL`, `Put`); `aws-sdk-go-v2` behind `s3Store` (checksums only when required, explicit `ContentLength`, `ContentType` guessed from the key extension). `Get` is for small metadata (`index/…`, `.meta.json`, 1 MiB cap); missing keys return `errNotFound`. `ListKeys` enumerates every key under a prefix (startup index load) |
| `browse.go` | Calendar browse over the in-memory monthly indexes; size/time formatting, type icons and preview-kind helpers shared with the bundle detail page. A **bundle** is one pushed batch of files at `content/<uuid[:2]>/<uuid[2:4]>/<uuid>/` |
| `detail.go` | Dedicated bundle page `GET /bundle/{id}` (`detailData`): meta from the in-memory index with a `.meta.json` fallback, stats, type icons, inline media preview |
| `bundle.go` | Bundle layout helpers: UUID v4, `content/aa/bb/<uuid>/` prefix, `.meta.json` and monthly index JSON (`id`, `title`, `time`); `bundleIndex`, the in-memory copy of all monthly indexes |
| `upload.go` | Local upload workspace: list/add/delete under `upload.workspace`; `/upload` UI; `.filestor/` meta dir (`state.json`, `tmp/`, `analyze/`, `digest/`), startup `prepWorkspace` (clean stale temp files, clear analyze products), and `workspaceStateStore` (draft push options kept in memory, loaded from `state.json` at startup, write-through on change) |
| `events.go` | Shared SSE hub (`GET /upload/events`): lock, progress, files, state; workspace mutex |
| `push.go` | Async push of staged files to `content/<aa>/<bb>/<uuid>/` plus `.meta.json`, the `.filestor/digest/` marks into the bundle's `.digest/` subdirectory, and an append to `index/YYYY/YYYY-MM.json`; single-flight via the hub lock |
| `analyze.go` | LLM file analysis: prep pre-converts each staged file toward paged text and normalized images (products written into `.filestor/analyze/`), then a chat-completions tool loop (`read_file` / `load_media` / `rename_file` / `mark_text` / `mark_image` / `set_title` / `set_datetime`) ends when the model calls `finish`; `set_title` / `set_datetime` write `.filestor/state.json`, the marks land in `.filestor/digest/`, and a successful run sets its `analyzed` flag |
| `embed.go` | DashScope multimodal embedding client (`llm.embeddings.bailian_multimodal_embedding`): one HTTP request per digest file (text chunks as `text`, images as base64 data URIs; per-request image limits vary by model, so per-item stays model-agnostic), `dimension` only when configured, shared-dimension check |
| `vectors.go` | Aliyun OSS Vectors writer (`llm.vectors.aliyun_oss_vectors`): `PutVectors` over std `net/http` with a hand-rolled OSS4-HMAC-SHA256 header signature (canonical resource `/acs:ossvector:{region}:{account_id}:{bucket}/`; region from the 地域节点 `url`, Host `<bucket>-<account_id>.<endpoint>`); vectors keyed `<bundleID>/<digest file>` with bundle metadata |
| `convert.go` | Analyze-time pre-conversion (`pdftotext`/`pdftoppm` / `soffice` / ImageMagick / `pandoc` / `catdoc` / `ffmpeg`): full text, rendered document pages, normalized images, video frames; never mutates staging |
| `templates/*.html` | Embedded HTML. Bootstrap 5.3 (jsdelivr CDN, SRI) with `data-bs-theme="dark"` + Bootstrap Icons; keep SRI hashes matching nanollm unless bumping the CDN URLs |
| `web_tmpl.go` | `//go:embed templates/*.html`; template funcs `sub`, `jsAsset` |
| `web_static.go` | `//go:embed all:static/dist`; `GET /static/` serving with immutable cache; `jsAsset` matches `<entry>-<hash>.js` |
| `static/` | bun + TypeScript frontend: entries in `src/entries/*.ts` bundled by `build.ts` (`Bun.build`, IIFE, `[name]-[hash].js`) into `dist/`; `bun run build` / `bun run dev` (watch) / `bun run typecheck`; `dist` is git-ignored except `.gitkeep` |

Tests live next to the code (`*_test.go`). Use `github.com/stretchr/testify`. Prefer extending an existing test file over adding a new one for the same area. HTTP tests inject `fakeStore`; never hit a real object store.

## Hard constraints

- **std `net/http` only** for the server. No Fiber/Gin/Echo.
- Config shape is `admin.{username,password}`, `s3.{endpoint,region,bucket,access_key_id,secret_access_key}` (all required), optional `s3.force_path_style` (MinIO-style vendors), optional `upload.workspace` (default `upload-workspace`), and the **required** LLM trio: `llm.chat.openai.{url,model,effort,headers}` (OpenAI-compatible chat endpoint for `POST /upload/analyze`; `effort` is the model's reasoning effort, `headers` is a map of extra HTTP headers), `llm.embeddings.bailian_multimodal_embedding.{url,model,headers,dimensions}` (DashScope multimodal embeddings endpoint; `dimensions` optional), and `llm.vectors.aliyun_oss_vectors.{url,bucket,account_id,access_key_id,access_key_secret,index}` (Aliyun OSS Vectors index; `url` is the console 地域节点 `<region>.oss-vectors.aliyuncs.com`, `bucket` is the vector bucket name, `account_id` is the Alibaba Cloud account UID). A missing LLM field fails startup. Every `llm.*.url` must carry an `http(s)://` scheme. Every push embeds the digest marks (one embeddings request per digest file, `Authorization` carried by `headers`) and writes the vectors into the OSS Vectors index keyed by bundle id. Names follow the **S3 multi-vendor convention** (`secret_access_key`, `region`, `force_path_style` — as in litestream/rclone), not vendor-specific APIs. `endpoint` may omit `https://`; `normalizeEndpoint` adds it on load. Aliyun OSS needs its S3-compatible endpoint (`https://s3.oss-{region}.aliyuncs.com`).
- **Do not proxy object bytes.** `GET /download?key=` signs a GET URL (`signURLTTL` = 5 minutes, `ResponseContentDisposition(attachment)`) and 302s to the bucket. `GET /preview?key=` signs **without** the attachment disposition so the browser renders browser-native media inline; CSP allows `img-src`/`media-src https:` for those signed URLs (plus `http:` when the configured endpoint is plain http). `ObjectStore.Get` is only for small JSON metadata (monthly indexes and `.meta.json`, capped at 1 MiB).
- Listing uses `ListObjectsV2` with `Prefix`, `Delimiter("/")`, `StartAfter`, `MaxKeys(200)`. Skip the placeholder object whose key equals the current prefix. If a page is truncated, resume from the last listed object key or common prefix (`StartAfter`; no `ContinuationToken` plumbing).
- Browser lives at **`GET /browse`**. `GET /` is an unauthenticated 302 to `/browse` so `/` can host other pages later. Navbar brand stays `href="/"`. The navbar is fixed (`fixed-top`; `body` gets `padding-top` from the small `<style>` block in `base.html`, which CSP's `style-src 'unsafe-inline'` permits). Login success and already-logged-in `GET /login` redirect to `/browse`. Browse links stay under `/browse?...`, never `/`. With no params, `/browse` renders a **calendar** for the current month (weeks start Monday) from the **in-memory monthly indexes** (`bundleIndex`; loaded once at startup from `index/YYYY/YYYY-MM.json` — a file that fails to read or parse is logged, skipped on the calendar, and marked broken — pushes into that month are refused rather than rewriting the bucket file from the incomplete in-memory copy — and updated by every successful push; calendar requests never touch the bucket): days holding a bundle are highlighted from that month's own entries, and landing selects today. `?month=YYYY-MM` switches months, `&day=YYYY-MM-DD` selects a day (out-of-month days are dropped). The right pane lists **every bundle day of the displayed month's year**, newest first, each group anchored `id="day-YYYY-MM-DD"`; the calendar card is `position-sticky`, calendar day links and the bundle-view back link carry `#day-...` fragments, and `static/src/entries/browse.ts` scrolls the selected (or today's) group into view when the URL has no hash. A selected day without bundles shows a "No bundles on …" hint. Clicking a bundle opens the dedicated **`GET /bundle/{id}`** page (UUID v4 path segment; 400 on a non-UUID id), rendered from `templates/bundle.html` with meta from the in-memory index (id, title, `YYYY-MM-DDTHH:mm`; falls back to the bucket's `.meta.json` for bundles the index does not know — missing from both, or invalid meta, is a 404): back link to the day, title + date/time header, file count and total size (`.meta.json` is omitted from the listing, and the `.digest/` subdirectory never lists at all — the delimited listing returns it as a common prefix, not as objects), type-aware icons, image gallery and `<video>`/`<audio>` players over `/preview` signed URLs (images over 32 MiB stay download-only). There is no generic prefix browsing: `/browse` is calendar-only and object keys are reachable through the bundle pages. A day given without a valid month pulls its own month into view.
- `/browse`, `/bundle/`, `/download`, `/preview`, `/static/`, and `/upload*` are cookie-protected. `GET /healthz` and `GET /` are not. Cookie: HMAC-SHA256 over `username|expiry`, HttpOnly, SameSite=Lax; `Secure` when TLS or `X-Forwarded-Proto: https`. TTL 12 hours; key is derived from username+password so a password change invalidates sessions. Failed login delays 1s. Constant-time compare via SHA256 of credentials.
- `http.Server.Shutdown` uses an unbounded context: SIGINT/SIGTERM stops accepting connections and waits indefinitely; after the first signal, SIGINT/SIGTERM is unregistered so a second signal can terminate. Do not add a Shutdown timeout.
- **`/upload` is a local staging directory plus a bucket push.** `GET /upload` + `GET|POST|DELETE /upload/files` manage staging: write files under `upload.workspace` (create the dir if missing), list only regular files in the workspace root, skip subdirectories and dot-prefixed hidden files (incl. the `.filestor/` meta directory). Sanitize names with `path.Base`; reject empty names and any dot-prefixed (hidden) name, which covers `.`, `..`, and `.filestor`. The UI also skips folder drops and hidden files client-side, pre-checks the 2 GiB per-file limit, and stages files sequentially (one XHR `POST` per file) so it can show real per-file/overall byte progress; a failed file does not abort the rest of the batch. Do not serve workspace bytes. Multipart field is `file`; max request size 2 GiB. The first staged file pins the draft push options (`time` = now, `title` = "") in `.filestor/state.json` as soon as that file is saved; `PUT /upload/state` (form `time` + `title`, called by the page on input change) updates them while files are staged (no-op on an empty workspace). The page prefills both inputs from this state, so a reload keeps the pinned time. The Analyze button is always shown (the chat endpoint is required config); pushing requires one successful analyze run — a success sets `analyzed` in `state.json`, staging add/delete clears it (`state.markUnanalyzed`, which also drops the digest marks), and the page disables the upload button (`POST /upload/push` returns 400) until the next analysis. The state file is removed when staging empties (the digest directory with it) — all files deleted or a successful push that leaves nothing behind (files added on disk during a running push stay staged and keep the state). The draft state lives in memory (`workspaceStateStore` on the server): the file is loaded once at startup like the monthly index, reads hit memory, and every mutation writes through to `state.json` (memory updates only after the write lands). All non-staged files live under the workspace's hidden `.filestor/` directory: `state.json`, `tmp/` (atomic-write temp files for uploads and state), `analyze/` (per-run model-readable products), and `digest/` (the run's content digest marks). `prepWorkspace` (called by `NewServer`) creates it, removes stale temp files, and clears `analyze/`. Staging add/delete, analyze, and push share one exclusive workspace lock (`stage` / `analyze` / `push`); a second mutation gets 409. `PUT /upload/state` is 409 while analyze or push holds the lock. `GET /upload/events` (SSE) pushes `snapshot` / `lock` / `files` / `state` / `progress` / `done` / `error`; the page uses EventSource instead of polling. A subscriber whose event buffer fills is disconnected, so its EventSource reconnects to a fresh snapshot instead of silently missing events; acquiring a lock clears the previous job so stale results never render under a new operation. Staging byte progress stays on XHR `upload.onprogress`.
- **LLM file analysis is an async tool loop.** `POST /upload/analyze` (503 if the chat endpoint is missing from the loaded config — it is required in practice, 400 on empty staging, 409 if the workspace is locked) acquires the `analyze` lock, then snapshots the staged files, returns 202, and runs a chat-completions tool loop in a background goroutine against `llm.chat.openai.url` with std `net/http` (`reasoning_effort` from `llm.chat.openai.effort`, extra headers from `llm.chat.openai.headers`). The round/tool-call budget scales with the staged file count (`analyzeBudget`: 16 rounds / 28 tool calls for a single file, +1 round and +2 tool calls per extra file, capped at 64 rounds / 256 tool calls). The run starts with a prep phase (`prepAnalyze`, one `converting` progress event per file): each staged file is classified (extension first — the document/image/video sets — then NUL-sniffing the first 8 KiB; an `.svg` is text but stays an image) and pre-converted, best effort, toward the two model-readable forms — paged text and normalized images — with a per-file timeout (120 s documents/videos, 45 s images). Documents get both a full text (≤4 MiB) and up to 6 rendered page images (≤4 MiB each; `pdftoppm -jpeg -r 150` is the primary PDF path — Debian's ImageMagick 6 policy forbids PDF — office documents go through a soffice PDF export first, with magick `[0-5]` and a single soffice png page as fallbacks), non-native or oversized images get one normalized jpg (small native jpeg/png/gif skip conversion and load straight from staging), videos get 3 ffmpeg frames (`fps=1/5,scale=1280:-2`), and unknown binaries ≤64 MiB get one best-effort soffice/pandoc text attempt (larger ones are judged by name only). A file whose conversions all fail is marked `conversion failed` and never aborts the prep. Products are written into `.filestor/analyze/` — cleared and rebuilt by every run — under names that mirror their source: `<name>.txt`, `<name>.pNN.jpg`, `<name>.fN.jpg`, `<name>.jpg`. The initial user message lists each staged file with its size and kind (names `backtick`-quoted) plus its converted forms indented below (text forms with line counts, native text also with a one-line `peek:` at the first 1 KiB, whitespace-collapsed), and the prompt tells the model to skip very large files instead of reading them and to `load_media` a document's page images when its text form is missing or too short (scanned, all-image documents). The prompt prescribes a fixed workflow: inspect the files, then every on-demand rename (before any marking), then the digest marks, then title/datetime last. The loop ends when the model calls `finish` — a round without any tool call is answered with a nudge to keep analyzing or finish — and `set_title` no longer ends the loop early: a run succeeds once a title is set. When the budget runs out the loop does not fail: reading is closed and one forced wrap-up round offers only the output tools (`set_title`/`set_datetime`/`mark_text`/`mark_image`/`finish`), accepting a sanitized plain-text answer as a last resort. Progress and the chosen title/time go over SSE (errors are not echoed from the upstream LLM). Eight tools: `read_file` (sanitized name resolving to a staged text file or a derived `name.txt` in `.filestor/analyze/`; reads are paged — 1-based `offset`, `limit` default 200 / max 500, the reply capped at 64 KiB with a `lines X-Y of N` header, staging text readable only up to 8 MiB — and calling it on a document/image/video source name errors and points at the derived forms), `load_media` (a staged image/document/video name loads all its derived images at once — pages ≤6, frames ≤3 — as multiple image parts in one user message; a single derived image name loads just it; jpeg/png/gif only to the model, 8 MiB each, mimes re-sniffed from the bytes), `rename_file` (renames a staged file whose name is messy, uninformative, or carries a redundant/wrong date, only when the model is confident; both names are sanitized, overwriting a different existing file is refused, the file's derived forms in `.filestor/analyze/` are renamed with it, the reply returns the complete updated roster, and a `files` SSE event refreshes the page), `set_datetime` (optional; writes only `Time` into `.filestor/state.json` when the model finds a clear document date, `YYYY-MM-DD` or `YYYY-MM-DDTHH:mm`, keeping the title), `set_title` (writes only `Title`, keeping the pinned time; a run only succeeds with a title), `mark_text` (submits one small, independently indexable text chunk — the model chunks the important text itself, quoting or slightly tightening the source — written as its own `text-NN.txt` under `.filestor/digest/`; at most 16 chunks of 8 KiB each), `mark_image` (marks one content-bearing image for the digest — a native staged image or a single derived image name; a document/video source name stands for several images and is refused with a pointer at the derived names — copied to `image-NN-<name>` under `.filestor/digest/`; at most 4 images, repeated marks deduped; the prompt has images whose text the chunks already cover skipped, and textless or unextractable images — photos, diagrams, scanned pages — marked), `finish` (ends the analysis once every output is done). The digest directory is the batch's content digest for the later embedding step: rebuilt empty by every analyze run, dropped when the staged set changes and when the draft state is cleared, and removed at startup when no state file exists. A successful run then sets `Analyzed` in `.filestor/state.json` (a failure leaves it untouched). Tool-call `arguments` may be a JSON object or a JSON string containing one. Conversion CLIs (incl. poppler-utils and `ffmpeg`) are installed in the container image; local `go run` still serves native text and small jpeg/png/gif.
- **Push to the bucket is async and single-flight.** `POST /upload/push` (form `time` = `YYYY-MM-DDTHH:mm` wall clock, `title`; 400 while the staged files are not analyzed — the chat endpoint is required config) snapshots the staged files, acquires the `push` lock, and starts a background job that generates a UUID v4, `Put`s each staged file into `content/<id[:2]>/<id[2:4]>/<uuid>/<name>` (title sanitized: letters/digits/`_`/`.`, everything else folds to `-`, max 80 runes), then any digest marks from the analyze run into the bundle's `.digest/` subdirectory (a missing digest directory means there was nothing to mark), then — via the configured embeddings endpoint — embeds each digest file (one request per file, progress as `embedding digest i/n`) and writes the vectors into the OSS Vectors index (keyed `<bundleID>/<name>` with the bundle's title/time in metadata), then `.meta.json` (last, so an interrupted job leaves no discoverable bundle behind), then appends `{id,title,time}` to the monthly index: the bucket file `index/YYYY/YYYY-MM.json` is rewritten from the in-memory month plus the new entry (month taken from the picked time; a missing month starts as `[]`), and the in-memory index is updated only after that write lands. Each staged file is removed only after the index write lands, then a `files` event is broadcast so the page list matches disk; the first failure stops the job (and skips the index update) and keeps everything staged for a retry. Only one workspace job runs at a time — a second `POST` gets 409. Progress is broadcast on `GET /upload/events` (byte updates throttled ~10Hz). The job goroutine is not joined on shutdown.
- **Page JS is TypeScript, not inline.** Entries live in `static/src/entries/*.ts`; `bun run build` (in `static/`) bundles each into a self-contained IIFE named `<entry>-<hash>.js` under `static/dist/`, which is embedded and served at `GET /static/` with immutable caching. Templates reference entries only by name via `{{jsAsset "entry"}}`; CSP `script-src` allows `'self'`. `static/dist` is git-ignored (only `.gitkeep` is committed), so run the frontend build before `go build` — the Dockerfile does it in an `oven/bun` stage.
- There is no search or multi-bucket UI unless asked.
- Do not commit `config.yaml` (secrets). Change `config.example.yaml` and README when the config schema changes.
- Images: `ghcr.io/${{ github.repository }}`. Push `main` → `latest`; push a git tag → that tag. Workflow: `.github/workflows/release.yml`. Image sets `FILESTOR_CONFIG=/config.yaml`. Flags/env: `-config`/`FILESTOR_CONFIG` default `config.yaml`; `-listen`/`FILESTOR_LISTEN` default `:8080`.

## Style

- Match nearby files: `log` package, table-driven tests, `httptest` for HTTP.
- `main` may use `rg.Must` / `rg.Guard`; library-ish functions return `error`.
- Keep YAML config the only user-facing knobs besides listen/config flags.
- Public docs and fixtures: placeholders (`example-bucket`, `REPLACE_ME`), never real secrets.
- Do not hit a real object store in unit tests; inject `ObjectStore` (`fakeStore` in `browse_test.go`).
